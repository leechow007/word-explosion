# 词爆 · 标记体系产品设计（Word Marking）

> 目标：让用户用**最低成本**表达「这词我认识 / 不认识 / 别再弹了」，并让这套标记真正影响后续弹出策略。
> 状态：**设计稿，待确认后开发**。本文只定义产品逻辑，不涉及实现改动。

---

## 1. 现状与问题

当前交互只有一种语义：**双击 = 点爆消失**（只累加统计），**飘走 = 什么也没发生**。

因此：
- 我**认识**的词 → 后面还会一遍遍弹，浪费时间；
- 我**不认识**的词 → 和认识的词一样随机出现，得不到重点复习；
- 学习行为没有被记录，无法支撑后续的"记忆曲线"。

## 2. 核心模型：一个词 = 一个状态

引入与词库**解耦**的「词状态」（按单词文本记录，内置词库/导入词库共用同一份状态）。

| 用户可见状态 | 用户语义 | 对出现策略的影响 |
|---|---|---|
| **未标记**（默认） | 还没表态 | 正常随机出现（权重 1.0） |
| **生词** | 我不认识，多考我 | **高频复现**（权重 ≈ 3.0，优先补位进下一波） |
| **认识** | 认识，但可以偶尔复习 | **低频复现**（权重 ≈ 0.25，可随时间回升） |
| **已掌握** | 我熟了，别再弹 | **不再出现**（权重 0，可随时恢复） |

设计取舍：
- 只保留 **3 个用户可见状态 + 1 个默认态**，避免"生疏/模糊/熟练…"这类状态膨胀带来的选择困难。
- 状态**唯一**：一个词只能处于一个状态，后标记覆盖先标记（不存在"既是生词又是已掌握"）。

## 3. 标记入口（按"顺手程度"分层）

### 入口 ①：hover 释义卡（主入口，P0）
卡片本来就是为了"看释义后做判断"而弹出的，所以在卡片上给出标记按钮最自然：

```
┌──────────────────────────────────┐
│  expedite                  🔊    │
│  vt. 加快；促进；发出             │
│  ──────────────────────────────  │
│  [ 🤔 不认识 ]      [ ✅ 已掌握 ] │
└──────────────────────────────────┘
```
- 「不认识」→ 标记生词，卡片按钮变为已选中态（可再点一次取消）。
- 「已掌握」→ 标记已掌握，词泡立即飘走（不再需要占用屏幕）。
- 卡片是交互窗口，此前已修好"够得到按钮"的问题，复用同一套 hover 保持逻辑。

### 入口 ②：双击语义（P0，可关闭）
把最主要的动作赋予明确语义：

| 动作 | 语义 | 说明 |
|---|---|---|
| **双击词泡** | **认识**（降权） | 保持现有爽快感，不增加任何操作 |
| **⌥ + 双击** | **不认识** | 想加强学习时用，一步到位 |
| **⇧ + 双击** | **已掌握** | 明确"别再弹" |

- 设置项「双击视为『认识』」默认**开启**；关闭后双击只清屏、不改变状态（适合把清屏当默认动作的用户）。
- 修饰键动作可在设置里关闭（避免误触）。

### 入口 ③：菜单栏（P1）
- 波次结束时，菜单栏状态行可显示「本波 2 个生词」，点开可查看/撤销。
- 菜单里提供「撤销上次标记」（3 秒内有效，防误标）。

### 入口 ④：设置 → 词库 → 我的标记（P1，管理面）
三个筛选页签：**生词 / 已掌握 / 全部已标记**，支持：
- 搜索、逐条改状态、批量恢复（把已掌握改回未标记）；
- 空态提示 + 数量徽章。

> 「一键把生词导出到我的词本」已列入 v1.0 路线，v0.2 先不做（按已确认决策只提高复现频率）。

### 入口 ⑤：词库列表内直接标记（P2）
「我的词本」列表每行加状态徽章，不依赖弹出即可标注（适合导入后先手动筛一遍）。

## 4. 弹出策略（标记如何生效）

由"完全随机"升级为**加权随机 + 冷却**：

```
选词权重 = 状态基础权重 × 冷却系数
  状态权重：生词 3.0 / 未标记 1.0 / 认识 0.25 / 已掌握 0（排除）
  冷却系数：最近 2 波出现过的词 ×0.2；最近点爆过的词再 ×0.5
生词优先补位：若存在生词，每波至少包含 1 个（可在设置关闭）
波容量：wordsPerWave 不变（默认 6）
```

补充规则：
- **认识的权重回升**（可选，默认关）：7 天未被复习的"认识"词权重从 0.25 升到 0.5，避免长期不复习遗忘。
- **可复习词耗尽**：若可用词（非已掌握）数量为 0，不发波，菜单栏提示「可复习的词用完了，去设置恢复一些」。
- **波次内不重复**：同一波内不出现同一个词（现有逻辑保留）。

## 5. 标记发生的瞬间（交互反馈）

| 标记 | 词泡行为 | 反馈 |
|---|---|---|
| 认识（双击） | 点爆动画后消失 | 统计 +1，卡片收起 |
| 不认识 | 点爆动画后消失（本次已看） | 卡片按钮选中；菜单栏生词数 +1；可选轻触感 |
| 已掌握 | **立即飘走**（不再等待点爆） | 卡片收起；菜单栏提示已掌握 +1 |

> 说明：标记后词泡都从屏幕上消失，避免残留堆积；差别在于**下次出现的概率**。

## 6. 数据模型与存储

```jsonc
// ~/Library/Application Support/WordPop/marks.json
[
  {
    "word": "expedite",        // 小写作为唯一 key（与词库解耦）
    "state": "unknown",        // unknown | known | mastered | (未标记则不存)
    "seenCount": 12,           // 弹出过多少次
    "popCount": 5,             // 点爆过多少次
    "unknownCount": 3,         // 被标记为"不认识"的次数
    "lastSeenAt": "2026-09-21T10:00:00Z",
    "updatedAt": "2026-09-21T10:00:00Z"
  }
]
```

要点：
- **与词库解耦**：换词库、清空导入词本、重装内置词库，标记都不丢；
- 顺带记录 `seenCount / popCount`，为 v0.3 的**记忆曲线（1/2/4/7 天复现）**打好数据基础；
- 词库导入/合并时按 `word` 匹配已有标记（同名词自动继承状态）。

## 7. 边界与容错

1. **误标**：标记后 3 秒内可从菜单栏「撤销上次标记」；或在标记管理页改回。
2. **全部已掌握**：不发波 + 明确提示，提供「恢复全部已掌握」。
3. **同一词多词库**：状态唯一，按 word 合并。
4. **导入词表里含已掌握词**：状态保留，不因重新导入而重置。
5. **未标记词占多数**时策略退化为现有随机行为（向后兼容）。
6. **已掌握词不进入统计的"弹出"计数**，避免虚高。

## 8. 设置项（新增）

| 分组 | 设置 | 默认 | 说明 |
|---|---|---|---|
| 学习 | 双击视为「认识」 | 开 | 关闭后双击只清屏 |
| 学习 | 启用 ⌥/⇧ 双击标记 | 开 | 修饰键快速标记 |
| 学习 | 生词加频倍数 | 3× | 1–5× |
| 学习 | 「认识」词复现权重 | 0.25 | 0.1–1.0 |
| 学习 | 「认识」词 7 天后权重回升 | 关 | 抗遗忘 |
| 学习 | 每波优先带 1 个生词 | 开 | 有生词时生效 |

## 10. 关键指标（验证是否有效）

- 标记使用率：每 100 次点爆产生多少次标记（目标 ≥ 20）；
- 生词重投效果：生词在 7 天内被点爆 ≥ 3 次的比例；
- 已掌握词回流率（用户主动恢复的比例，过高说明误标多）；
- 用户是否关闭「双击视为认识」开关（比例高说明默认语义不合直觉）。

## 11. 已确认决策（锁定）

| # | 决策点 | 结论 |
|---|---|---|
| 1 | 双击语义 | **双击 = 「认识」（降权）**；设置项「双击视为『认识』」默认开启，可关；`⌥+双击` = 不认识，`⇧+双击` = 已掌握 |
| 2 | 状态数量 | **三态：生词 / 认识 / 已掌握**（+ 默认「未标记」） |
| 3 | 已掌握强度 | **永久不再出现**，仅可通过「我的标记」页手动恢复（不做 30 天抽查） |
| 4 | 生词处理 | **只提高复现频率**（权重 ×3 + 每波优先带 1 个）；「导出成我的词本」推迟到 v1.0 |

由此确定的 v0.2 实现范围：
1. `marks.json` 词状态存储（与词库解耦，含 seen/pop 计数）
2. 加权随机 + 冷却的选词调度（生词 3.0 / 未标记 1.0 / 认识 0.25 / 已掌握排除）
3. 标记入口：hover 卡片两个按钮（不认识 / 已掌握）+ 双击=认识 + ⌥/⇧ 双击 + 菜单栏 3 秒撤销
4. 设置新增「学习」分组（双击语义开关、修饰键开关、加频倍数、认识权重、生词优先补位）
5. 「我的标记」管理页（生词 / 已掌握，搜索、改回、批量恢复）
6. 统计区分「点爆」与「标记」，已掌握词不计入弹出统计
